# 示波器 QA 与镜头匹配

## 为什么需要这两步

单条调色"看着对"和"交付合格"是两件事。实测五条成片：

| 片段 | 中间调 | 动态范围 | 饱和 | R−B |
|---|---|---|---|---|
| 水果 | 0.625 | 0.702 | 0.508 | +0.339 |
| 食材 | 0.426 | 0.677 | 0.542 | +0.322 |
| 城市 | 0.087 | 0.576 | 0.422 | −0.014 |
| 瀑布 | 0.283 | 0.684 | 0.222 | −0.013 |
| 人群 | 0.497 | 0.900 | 0.341 | −0.001 |

中间调跨度 **0.538**、色偏跨度 **0.379**。每条单独都"对"，连起来就是五条不同的片子。

## 示波器（`scopes.py`）

```bash
python scripts/scopes.py OUT/xxx_graded.mp4 --out qa.jpg
```

输出波形、RGB 分离、矢量图，同时打印硬指标：

| 指标 | 合格线 | 说明 |
|---|---|---|
| 高光溢出 | < 1% | 堆在 100% 线上的像素已经没细节了 |
| 死黑 | < 1% | 同上，压在 0% |
| 通道溢出 | R/G/B 各 < 0.5% | 单通道先爆会让颜色先失真 |
| R−B | < ±0.10 | 超出即明显偏色 |
| 肤色色相 | **30–37°** | >42 偏黄，<26 偏红 |

实测一例：`高光溢出 0.00%、死黑 0.15%、R−B +0.334、肤色 26.7°` ——
曝光健康，但**肤色被推红了 3 度多**，这是调色时看不出来的，只有量才知道。

**肤色线是最有说服力的单一指标。** 人眼对肤色极其敏感，但它偏偏在小图上最难判断。

## 镜头匹配（`match_shots.py`）

```bash
python scripts/match_shots.py --in GRADED_DIR --out MATCHED_DIR [--reference auto|NAME]
```

1. 量每条成片的中间调/动态范围/饱和/色偏
2. 选一条基准（默认取最接近全组中位数的，也可指定）
3. 推导每条需要补多少曝光、对比、白平衡
4. 烘成一个小 `match.cube`，**接在 look LUT 之后**
5. 重渲后**再测一遍**，输出离散度改善

实测：中间调跨度 **0.538 → 0.136**（收窄 75%）。

### 三个必须知道的点

**① 饱和度默认不匹配，这是故意的。**

瀑布本就该比水果饱和低——那是**内容属性，不是一致性缺陷**。跨场景匹配饱和会把整组压平。
只有在**同一场景、同一布光**下才用 `--match-saturation`。

**② 匹配的前提是"同一条片子里的不同镜头"。**

拿五段毫不相干的素材去匹配，技术上能跑（亮度确实齐了），但把夜景提亮到和日景一样
并不好看。**匹配服务于序列，不是服务于"数字好看"。**

**③ 匹配要做在渲染链里，不要二次转码。**

`render_v5.sh` 支持 `POST_LUT`：

```bash
CLIPS=xxx POST_LUT=match.cube bash scripts/render_v5.sh
```

接在 look LUT 之后、清晰度之前。这样只有一次编码，没有二次代际损失。
`match_shots.py --src` 会自动走这条路；不给 `--src` 才退化成转码。
