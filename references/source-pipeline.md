# 源头类型：调色之前必须先确定的事

## 为什么必须先做这一步

小米 15 Ultra 的**HDR 视频模式**和**Log 视频模式**写出的元数据是**一样的**：

```
color_primaries = bt2020
pix_fmt         = yuv420p10le
color_transfer  = unknown      <-- 两者都是 unknown
```

`ffprobe` 分不出来，`mediainfo` 也分不出来。但这两类信号需要的处理**完全相反**：

| | HDR（PQ） | Log |
|---|---|---|
| 信号特征 | 高光保留了大量亮部信息，暗部压缩 | 整体又暗又平，动态范围摊开 |
| 正确做法 | **色调映射**：PQ→线性→tonemap→709 | **源 LUT**：Log→linear→709 |
| 用错会怎样 | 当 Log 处理 → **高光撞白、过饱和** | 当 HDR 处理 → **发灰、发暗、对比丢失** |

**这是"调完感觉不对但说不清哪不对"最常见的原因。**

---

## 实测案例（值得记住的数字）

同一帧、同一条素材，三种处理方式的客观指标：

| 处理方式 | 平均亮度 | 对比 | 饱和度 | 与正确结果差 |
|---|---|---|---|---|
| 直出（不转换） | 0.365 | 0.215 | 0.263 | 11.5/255 |
| **Log 系 look LUT 套 HDR 素材** | 0.336 | 0.328 | **0.585–0.673** | 20.4–23.7/255 |
| **正确的 PQ 色调映射** | 0.336 | 0.254 | **0.432** | 基准 |

看清楚那个饱和度：**0.67 对 0.43，高出 50%**。原因是 Log 信号本身很灰，为 Log 设计的
look LUT 里塞了大量增益来"补偿"；把它套到本来亮度正常的 PQ 素材上，等于补偿了两次。

画面上表现为：蛋液、灯管、白手套全部撞白，颜色艳得发假，暗部却仍然是灰的。

## 判定流程

```bash
python scripts/detect_source.py "素材目录" --out source_check
```

脚本会把同一帧按三种解释各渲一遍，按"这像不像一个正常的 Rec.709 画面"打分：

```
路线      得分     亮度     对比    动态范围   高光溢出%  死黑%
pq       88.9   0.308   0.157     0.494       0.02    0.0   <<<
sdr      55.1   0.325   0.122     0.388        0.0    0.0
hlg      45.2   0.324   0.111     0.359        0.0    0.0
=> 判定: PQ
```

**关键判据是"动态范围"（p95-p05）**：被错误解释的 HDR 会把所有色阶挤在中间，
动态范围明显偏小（0.388 / 0.359 对 0.494）。这比看对比度可靠——低对比场景
（雾、蒸汽）本身对比就低，会干扰判断。

**分数只是筛子，不是判决。** 脚本同时输出 `source_check.jpg` 三联对比图，
**必须看一眼**再定。分数线：>55 认为是该路线，两路线差 <4 分时会提示确认。

## 三条路线对应的命令

### PQ（HDR10）

```
zscale=tin=smpte2084:min=bt2020nc:pin=bt2020:rin=full:t=linear:npl=100,
format=gbrpf32le,zscale=p=bt709,tonemap=hable:desat=0,
zscale=t=bt709:m=bt709:r=tv,format=yuv420p10le
```

### HLG

同上，`tin=arib-std-b67`。

### Log

**不要用上面任何一条。** Log 需要它自己的源 LUT（从 camera maker 提供或标定得到），
顺序是：

```
Log 源 LUT（→ Rec.709） → 一级校正 → look LUT → 输出
```

在 Resolve 里就是节点 01 `SOURCE` 放源 LUT，和六节点 PowerGrade 的设计一致。

### SDR

不转换，直接进一级校正。

## 常见误区

**"文件是 10bit BT.2020，所以肯定是 HDR"** —— 不对，Log 也是这么存的。

**"transfer=unknown 所以按 SDR 处理"** —— 不对，那是没标签，不是没信息。

**"用 Log 的 LUT 试试，反正差不多"** —— 实测差 20/255，饱和度差 50%，差很多。

**"HLG 和 PQ 都是 HDR，随便选一个"** —— 选错会偏暗偏灰（HLG 解 PQ）或过曝（PQ 解 HLG）。
用同一帧渲两种对比，一眼就能判断。

## 和 CFR 的关系

源头判定完成后，**编码时还有一件必做的事**：手机素材是 VFR，必须强制恒帧：

```
-r 60 -fps_mode cfr
```

不加的话，`avg_frame_rate` 会是 59.7 这种值，导入剪映/CapCut 后显示 30 帧。
这两件事（源头类型 + 恒帧）是手机素材交付的两个必过关卡，缺一个都会返工。
