# 三级调色管线：从"调了色"到"有质感"

## 为什么要分级

调色不是一组参数，是三个**作用范围完全不同**的操作。混在一起调，永远调不明白。

| 级别 | 作用范围 | 能否进 LUT | 解决什么 |
|---|---|---|---|
| **一级** | 全局逐像素 | ✅ 能 | 曝光准、白平衡准、对比对、肤色对 |
| **二级** | 空间局部（分区/遮罩） | ❌ 不能 | **主体与背景的分离感** |
| **三级** | 全画面质感 | ❌ 不能 | 光晕、柔和度、暗角、颗粒 |

**关键认知**：一级做十遍也做不出分离感。因为一级是全局的——把主体提亮，背景跟着一起亮。
分离必须靠二级的"一正一负"：主体 +，背景 −。这是量级上的差别，不是参数力度的问题。

## 流程

```bash
python scripts/render_levels.py CLIP.mp4 --out DIR --style cel_warm --levels 123 \
    --mask-preset band --mask-param 0.15 --halation 0.20 --vignette PI/12
```

`--levels` 可任意组合（`1` / `12` / `123` / `13`），方便对比各级贡献。

每一步在做什么：

1. **抽一帧**（走和渲染完全相同的滤镜入口），分析场景，推导曝光/白平衡/对比
2. **按这条素材自己的参数烘 LUT**（一级 + 风格）
3. **生成遮罩**（预设或手画多边形）
4. **组装链路并渲染**，强制 `-r 60 -fps_mode cfr`
5. **自动校验**时长与帧率

每条素材的参数都是独立推导的，所以同一套参数能吃夜景、日景、人像、风光。

---

## 作用顺序不能换

```
色调映射(HDR→709) → 一级LUT → 二级分区 → 三级质感 → 编码
```

- 三级放前面：halation 的光晕会把二级刚拉出来的分离糊掉
- 二级放一级前：等于在曝光还错着的画面上分区，白推

## 三个致命坑（全部实测踩过）

### 1. `maskedmerge` 在 YUV 上会整片去色

**现象**：加了二级之后，整幅画面发灰、去色，主体反而更暗。

**原因**：`maskedmerge` 在 YUV 上只门控**亮度平面**，色度平面被遮罩的中性值 128
拉到 50% 混合。

**验证方法**（两秒钟就能证伪）：

```bash
ffmpeg -f lavfi -i color=red:s=64x64:d=1 \
       -f lavfi -i color=blue:s=64x64:d=1 \
       -f lavfi -i color=white:s=64x64:d=1 \
       -filter_complex "[0:v][1:v][2:v]maskedmerge" -frames:v 1 t.png
# 输出 [107,0,106] = 品红，红蓝各半 —— 不是干净选区，说明色度被混了
```

**修法**：在 **RGB 域**做，且注意第二点。

### 2. 白遮罩选的是**第二路**输入

```bash
# 三路都在 gbrp 域，白遮罩 → 输出纯蓝
[红][蓝][白遮罩]maskedmerge → [0,0,254]
```

所以主体必须放**第二路**：

```
[背景][主体][遮罩]maskedmerge
```

写反了的表现是"主体变暗变灰"，很容易误判成"参数力度不够"，然后一直加参数——
越加越糟。

### 3. 颗粒会让码率爆炸

`noise` 是逐帧随机，天然不可压缩。实测 4K60、`alls=5`：

| 配置 | 码率 |
|---|---|
| 无颗粒 | 36 Mbps |
| 颗粒 strength=5 | **300+ Mbps**（6.86 秒出了 261 MB） |

**所以默认关闭。** 需要胶片颗粒感时用 `--grain 1~3`，并且先确认用户能接受文件体积。
更聪明的做法是把颗粒只加在暗部（亮部不动），码率能降一大半。

## 第四个坑：取帧路径必须和渲染链逐字一致

分析用的帧如果走 `format=rgb24`，而渲染走 `format=gbrpf32le`，两者电平会差 **~24/255**。
于是所有参数都是针对一张渲染器根本看不到的图算的。

**验证口径**：同一条链路下，Python 直算 vs 套 LUT，`mean|d|` 必须 **< 2/255**。
实测对齐后是 **1.18/255**。

## 实测效果（一条夜市烤串素材）

| | 主体亮度 | 背景亮度 | 亮度分离 | 饱和分离 |
|---|---|---|---|---|
| 仅一级 | 0.551 | 0.433 | +0.118 | +0.262 |
| 一+二+三级 | **0.569** | **0.376** | **+0.193** | +0.296 |

> ⚠️ 上表用的是**旧口径**（主体区 vs 画面边缘），已被证明受暗角污染，数字偏大。
> 正确口径的结论见文末「度量陷阱」：真实提升 **+12~19%**。此表仅作历史记录保留。

主体升、背景降，分离度有真实提升——但幅度见文末「度量陷阱」：用正确度量（主体 vs 紧邻背景环）
复核后是 **+12~19%**，早期宣称的 +64% 来自被暗角污染的指标，已作废。

## 遮罩怎么定（这是唯一需要逐条判断的环节）

`make_mask.py` 支持预设和多边形：

```bash
# 横向分区（主体占下半部分）
python scripts/make_mask.py --size 2160x3840 --preset band --param 0.15 --feather 0.055 --out m.png

# 手画多边形（相对坐标，任何形状）
python scripts/make_mask.py --size 2160x3840 --poly "0,0.15 1,0.15 1,1 0,1" --feather 0.05 --out m.png
```

**必须看一眼画面再定**。实测反例：一条素材用默认 `band 0.30`，而上排烤串从 18% 就开始了，
结果上排被当背景压暗了。

**羽化要大**（5%–8% 画幅高度）。硬边遮罩会在画面上留下一道看得见的界限。
镜头基本不动时，一张静态遮罩就够；要逐帧跟踪就得上达芬奇。

## 性能与批量

| 配置 | 速度 | 375 秒素材 |
|---|---|---|
| 仅一级 | ~50 倍实时 | 约 2 小时 |
| 三级全开 | ~33 倍实时 | 约 3.5 小时 |

`overlay` 在 4K 全画幅上很贵，`maskedmerge`（RGB 域）明显更快，优先用它。

**内存**：可用内存低于 3 GB 时渲染会崩溃式变慢（CPU 占满但产出极低），先让用户关掉吃内存的应用。

## 度量陷阱：我在这上面错了两次

### 第一次错：用「主体 vs 画面边缘」量分离度

暗角压暗的正是画面边缘。于是**加一个暗角，分离度数字就涨 30%**，而分区调色本身几乎没做事。
数字动了，画面没变好——这是**指标作弊**。

### 第二次错：因此断定"分区无效"

换成「主体 vs 紧邻背景环」（排除画面边框）后，结论反过来：

| 版本 | 主体 L | 紧邻背景 L | 分离 | 背景细节 σ | 死黑% |
|---|---|---|---|---|---|
| 仅 V5 | 0.280 | 0.085 | +0.194 | 0.064 | 0.24 |
| +二三级（含暗角）| 0.318 | 0.088 | **+0.230** | 0.072 | **1.97** |
| +二三级（无暗角）| 0.326 | 0.107 | **+0.218** | 0.077 | 0.00 |

**分区确实有真实效果**，但幅度是 +12~19%，不是我之前报的 +30%。

### 正确度量要同时看三件事

```bash
python scripts/measure_levels.py BEFORE.png AFTER.png --band 0.15
```

| 指标 | 为什么必须一起看 |
|---|---|
| 分离 | 主体 vs **紧邻背景环**，不是画面边缘 |
| 背景细节 σ | 亮度差涨了、细节却掉了 = 压出来的，不是分离出来的 |
| 角/中 比值 | 检测暗角污染。跌 0.10 以上说明分离数字里有边缘压暗的份 |

### 覆盖率的坑

遮罩覆盖率超过 **55%** 时，分区只剩一圈薄边可压，效果趋近于零还可能误伤主体。
`render_levels.py --l2-max-coverage` 默认 0.55，超过就**自动跳过 L2 并打印原因**。

实测：一条近景食物素材 `--mask-param 0.15` 时覆盖率 70%，等于拿主体自己当背景压。
